## Data Flow

### Theme Initialization
```
1. App Starts
   ?
2. ThemeProvider Reads appsettings.json
   ?
3. Loads Active Theme from themeDefinitions
   ?
4. Injects CSS Variables into document.documentElement
   ?
5. Components Render with Theme Applied
```

### Runtime Theme Change
```
User Action (Click Theme Button)
   ?
changeTheme('glassmorphism')
   ?
Validate: allowRuntimeSwitch === true
   ?
Validate: Theme Exists
   ?
Update State (setCurrentThemeName)
   ?
Trigger useEffect
   ?
Load New Theme from themeDefinitions
   ?
Apply CSS Variables to DOM
   ?
React Re-renders (Context Update)
   ?
Components Update with New Theme
```

## Component Integration Patterns

### Pattern 1: CSS Variables (Most Common)
```
Component (JSX)
   ?
Styled with CSS Module/File
   ?
Uses CSS Variables (--color-primary)
   ?
Variables Auto-Update on Theme Change
   ?
Component Re-styles Automatically
```

### Pattern 2: Theme Hook
```
Component Renders
   ?
Calls useTheme() Hook
   ?
Gets Current Theme Object
   ?
Uses Theme Values in Inline Styles
   ?
Re-renders on Theme Change
```

### Pattern 3: Theme-Aware Components
```
<Button> Component
   ?
Calls useTheme() Internally
   ?
Computes Styles Based on Theme
   ?
Applies Dynamic Styles
   ?
Auto-adapts to Any Theme
```

```

   ?

   ?

   ?

   ?

   ?
```

## Security Considerations

```
appsettings.json (Client-Side)
   ?
Contains Only Public Config
   ?
No Sensitive Data
   ?
Can Be Overridden by ENV Vars (Production)


For Production:
   ?
Move Sensitive Configs to Server
   ?
Use Environment Variables
   ?
Validate Theme Data Server-Side
   ?
Serve via API if Needed
```

## Performance Optimization

```
Theme Change Triggered
   ?
CSS Variables Updated (Instant)
   ?
Browser Re-paints (GPU Accelerated)
   ?
No Full Re-render Needed
   ?
Smooth Visual Transition


React Context Updates
   ?
Only Consumers Re-render
   ?
Memoization Prevents Excess Renders
   ?
CSS Modules Keep Styles Scoped
```

This architecture provides:
- ? Clear separation of concerns
- ? Easy to extend and maintain
- ? Performance optimized
- ? Type-safe (can add TypeScript)
- ? Testable components
- ? Production-ready
